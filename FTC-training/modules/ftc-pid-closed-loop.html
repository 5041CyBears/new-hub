Module Goals

By the end, students should be able to:

  • Explain the difference between open-loop output and closed-loop feedback control.
  • Describe what proportional, integral, and derivative terms do to a control error.
  • Use feedforward with feedback when a mechanism has predictable physical loads such as gravity or velocity demand.
  • Tune a mechanism methodically using target, measurement, error, output, and response data.
  • Recognize saturation, oscillation, noise, integral windup, poor gearing, and mechanical faults that software cannot fix.

Big Picture

The system at a glance

Feedback Loop

A closed loop repeatedly compares a target to a measured value, computes error, calculates an output, applies it, and measures again.

P — Proportional

P responds to current error. More error produces more correction. Too little can feel weak; too much can oscillate or overshoot.

I — Integral

I accumulates error over time and can remove persistent steady-state bias. It can also wind up badly when outputs saturate or the mechanism is blocked.

D — Derivative

D responds to how quickly error changes and can damp motion. Real sensor noise can make derivative terms noisy, so use them deliberately.

Feedforward

Feedforward predicts required output from the desired motion or known physics. Examples include gravity support for an arm or expected effort for velocity.

Mechanics First

PID does not repair backlash, binding, slipping belts, loose hubs, weak gearing, or poor sensors. Fix mechanical/electrical faults before tuning harder.

Core Knowledge

Important concepts

Units Matter

Know the units of setpoint, measurement, error, and output. A gain only has meaning relative to those units.

Output Limits

Motor output is limited. If the controller asks for more than available, the mechanism saturates and the integral term can continue accumulating unless handled.

Tolerance

Do not require exact equality. Define an acceptable position/velocity error and, where useful, a settling requirement.

Loop Rate

Control calculations depend on update timing. Keep the main control loop responsive and avoid unpredictable blocking work.

Built-In Motor Control

FTC motor controllers/SDK APIs can provide position/velocity modes. Understand what sensor, units, and controller behavior the selected mode uses.

Logging

Plot target, measurement, error, and output over time. A graph shows oscillation, lag, saturation, and disturbances far better than a single final number.

Practical Advice

What students should actually do

  • Log target, measurement, error, and output before changing gains.
  • Tune one mechanism axis at a time with the robot safely restrained and a clear stop method.
  • Start with conservative gains and increase deliberately; do not random-walk several gains at once.
  • Test multiple setpoints and loads rather than tuning only one perfect motion.
  • Check whether output is saturated. If the motor is already at maximum, more gain cannot create more voltage.
  • Use realistic tolerances based on scoring need and sensor/mechanism repeatability.
  • Reset/handle integral state when disabling, changing modes, or when accumulated error is no longer meaningful.
  • If tuning changes drastically after a mechanical repair, check whether the old controller had been compensating for a mechanical fault.

Competition Habits

Make the system repeatable and recoverable

Make state visible

Use labels, telemetry, logs, marks, checklists, or diagrams so students can tell what is happening without guessing.

Test failure modes

Create controlled bad conditions and practice safe recovery instead of testing only perfect operation.

Train backups

More than one student should know how to operate, explain, troubleshoot, and repair the system.
