Module Goals

By the end, students should be able to:

  • Identify the purpose of the Control Hub, Expansion Hub, battery, motor, servo, encoder, sensor, and USB connections.
  • Build a clean wiring layout that is reliable, inspectable, serviceable, and protected from strain.
  • Match software configuration names and ports to the physical robot.
  • Use a disciplined electrical troubleshooting order instead of replacing parts at random.
  • Recognize common FTC electrical failure modes including loose power, damaged USB, ESD, and overloaded mechanisms.

Big Picture

The system at a glance

Control Hub

The Control Hub is the center of the FTC robot control system. It runs the Robot Controller software and connects motors, servos, sensors, encoders, USB devices, and network communications.

Expansion Hub

An Expansion Hub adds additional motor, servo, encoder, and sensor ports. Treat it as part of the same electrical system: label it, secure it, and document what is plugged into every port.

Power Path

Battery power must reach every device through secure, legal connections. High-current connections deserve special attention because a loose connector can reset the entire robot.

Configuration

The active robot configuration tells the SDK what hardware exists and which ports it uses. A Java hardwareMap name must match the configured device name.

Signal & Data

Encoder, sensor, USB, and network connections carry information rather than mechanism power. Route and secure them so motion cannot pull, pinch, or repeatedly flex them.

Serviceability

A good electrical board is not just neat. Students should be able to identify a wire, reach a connector, replace a hub, and troubleshoot a failed device quickly.

Core Knowledge

Important concepts

Encoder Ports

The Control/Expansion Hub encoder inputs are not all implemented identically. Current FTC technical guidance notes that ports 0 and 3 are hardware-counted while ports 1 and 2 are software-counted; understand the implication when very high encoder rates matter.

Servo Power

Servo ports are grouped in power pairs: 0–1, 2–3, and 4–5. High-current servos can affect one another, so do not assume every servo problem is a programming problem.

USB Cameras

For webcams on a Control Hub, current FTC guidance recommends using the USB 3.0 port first. Secure the connector and provide strain relief so robot motion does not disturb it.

USB Cable Type

FTC documentation warns that USB-C-to-C cables do not work properly with the Control Hub for supported USB devices; use the specified USB-A-to-C style connection where required.

ESD

Static discharge can cause intermittent failures that look random. Protect electronics, follow FIRST wiring/ESD guidance, keep wiring off rubbing surfaces where possible, and investigate repeatable environmental patterns.

Inspection Mindset

Legal wiring still needs to be understandable. Use the current inspection checklist as the authority and make the robot easy for both inspectors and your own pit crew to understand.

Practical Advice

What students should actually do

  • Create a wiring map with hub name, port number, configured device name, and mechanism. Keep it with the robot.
  • Label both ends of important cables. Labels should match the names programmers see in the robot configuration.
  • Provide strain relief before connectors. A zip tie or anchor should take the mechanical load, not the plug.
  • Keep service loops where useful, but do not leave loose wire that can enter gears, belts, wheels, or slides.
  • After every major mechanical change, perform a tug/check inspection of nearby electrical connections.
  • When troubleshooting, change one variable at a time and write down what the test proved.
  • Use telemetry to distinguish 'software commanded zero' from 'software commanded motion but hardware did not respond.'
  • Before events, update only through a planned process, document versions, and keep a known-good software/configuration backup.

Competition Habits

Make the system repeatable and recoverable

Make state visible

Use labels, telemetry, logs, marks, checklists, or diagrams so students can tell what is happening without guessing.

Test failure modes

Create controlled bad conditions and practice safe recovery instead of testing only perfect operation.

Train backups

More than one student should know how to operate, explain, troubleshoot, and repair the system.
