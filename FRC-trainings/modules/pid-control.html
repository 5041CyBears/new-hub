Module Goals

By the end, students should be able to:

  • Explain proportional, integral, and derivative terms using error, accumulated error, and rate of error change.
  • Use the current WPILib PIDController correctly with consistent units and loop period.
  • Tune P first in many FRC cases, use I cautiously, add D only when it solves an observed problem, and combine feedforward with feedback.
  • Use tolerances, continuous input for angles, integrator limits/IZone strategies, logging, and controlled tests.
  • Recognize when motion profiling or ProfiledPIDController is more appropriate than jumping the position setpoint.
  • Diagnose oscillation, slow response, steady-state error, noise sensitivity, saturation, and windup.

PID in One Sentence

PID changes the actuator command based on the difference between what you want and what you measure

error = setpoint − measurement
output = kP·error + kI·∫error dt + kD·d(error)/dt

Always know the units of the setpoint, measurement, and output. A controller tuned in rotations cannot be copied directly to degrees or meters.

WPILib: WPILib provides PIDController, tolerance handling, continuous input, and related features; the default controller period is 20 ms unless configured otherwise. Open documentation
P, I, and D

Each term addresses a different shape of error

P — present error

Pushes harder when farther from the setpoint. Too high often oscillates or becomes unstable.

I — accumulated error

Can remove persistent bias but can wind up while saturated. Often avoidable in FRC when feedforward handles known loads.

D — error trend

Adds damping based on changing error. Can amplify noisy measurements and should solve a real problem, not be added automatically.

A Practical FRC Tuning Order

Do not tune three gains at once

  1. Verify sensor sign, actuator sign, units, and output limits.
  2. Build the best feedforward/model you reasonably can for mechanisms with predictable physics.
  3. Start P low and increase until response is useful but not unstable.
  4. Add D only if damping/overshoot needs it and the sensor is clean enough.
  5. Add I only when a persistent residual error remains and you understand saturation/windup.
  6. Log setpoint, measurement, error, output, battery voltage, and relevant current.

Saturation & Windup

The controller cannot command more voltage than the system can deliver

If output is saturated at its limit while I keeps accumulating, the stored integral can drive the mechanism past the target even after the error changes sign. Limit integral contribution or use an IZone strategy where appropriate—and fix the underlying impossible demand.

Feedforward + Feedback

Ask feedforward to do the predictable work

double ffVolts = elevatorFF.calculate(targetVelocity, targetAcceleration); double correction = pid.calculate(measuredPosition, targetPosition); motor.setVoltage(ffVolts + correction);

Exactly which state you feed into PID depends on the mechanism/controller design. Keep units and motor-controller semantics explicit.

Continuous Input

Angles wrap; ordinary subtraction does not know that

For a heading domain such as −180° to +180°, enabling continuous input lets the controller choose the shorter wrapped error instead of commanding a 358° turn from +179° to −179°.

Motion Profiling

PID tracks; a profile decides how aggressively the setpoint moves

ProfiledPIDController combines a trapezoidal setpoint profile with PID tracking. This is often better for elevators, arms, turrets, and mechanisms where an instantaneous position jump would demand unrealistic acceleration.

Practical Advice

Most “PID problems” are not fixed by randomly changing PID

  • Fix loose chain, backlash, flex, encoder slip, wrong conversion factors, and current limits before tuning.
  • Tune at realistic battery voltage and payload. Gravity and friction change with mechanism configuration.
  • Use conservative output limits during first tests.
  • Never compare gains without comparing units and controller period.
  • Log a step or profile response and annotate what gain changed between runs.
  • If the setpoint itself is physically impossible, motion profiling is often a better fix than enormous gains.
